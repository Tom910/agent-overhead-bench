# S3 diagnostic portfolio implementation plan

> For agentic workers: use subagent-driven-development and verification-before-completion.

**Goal:** Add runnable, reviewed development diagnostics for workflows missing from the eight public feature requests.

**Architecture:** Four compact original local tasks, each with written contract, isolated verifier, reference and materially different alternate implementation, targeted broken mutations and repeatability evidence through the new task-validity runner. Keep them in a separately labeled diagnostic stratum, outside the selected public-source campaign.

**Tech stack:** Python/Node standard libraries and existing task adapter; no npm dependencies, external downloads or agent/model calls.

**Spec:** Audit package 6. Four purposeful diagnostics are an initial coverage extension, not a claim that a 16-task representative public portfolio has been calibrated.

## Global constraints

Keep existing eight anchor tasks and historical measurements. No direct imports from prohibited benchmarks. These original small fixtures are not public-repository workload replacements or proof of long-context handling. Hidden verifiers, solution controls and failure mutations stay outside the staged agent workspace. No padding with irrelevant noise files.

## Review focus

All obligations stated before hidden tests; alternate implementations truly differ; targeted mutants fail their intended assertions rather than syntax/import errors; clean repetitions; bounded deterministic tests; correct diagnostic-only classification and provenance.
